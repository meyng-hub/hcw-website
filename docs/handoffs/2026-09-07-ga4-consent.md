**What the code does.** Everything is gated on `NEXT_PUBLIC_GA_ID`. Unset (the current state) =
no script, no banner, no cookies, zero analytics code shipped. Set = Consent Mode v2 defaults to
**denied** for all four signals, emitted as a plain inline `<script>` so it runs before the
`gtag('config')` that `next/script` defers to after hydration; `ads_data_redaction` is on while
denied; a FR/EN banner grants it, with refusal exactly as easy as acceptance and a
"Gérer mes cookies" control on the privacy page for withdrawal. Consent is read through
`useSyncExternalStore`, not an effect.

`<ConsentMode>` and `<GoogleAnalytics>` sit behind the **same constant**, so the tag structurally
cannot load without its consent defaults having run first.

**Conversion events:** `donation_complete` (on `/donate/merci`), `contact_form_submit`,
`volunteer_form_submit`.

### The bug this session found and fixed (the important one)

Privacy §6 claimed the site used **Plausible Analytics** — "no cookies, no third-party data
transfers, no cookie consent banner required". **Plausible is not installed and never was**; the
site runs Vercel Analytics. That false claim was live for months in both locales. It is now gone
(`grep -c Plausible` = 0 on both), and the section is **conditional on whether the tag is actually
configured**, so the page stays true before _and_ after the measurement ID is set.

This is the same failure class as the July fabricated-executive-team incident: placeholder content
is indistinguishable from verified content once it is in a file.

## ⚠️ OPEN — GA4 is still OFF, so Ad Grants still has NO conversion data

The plumbing is live; the tag is not. **This is the whole point of the exercise and it is not
done.** Two steps, both Michel's:

1. Create the GA4 property (no measurement ID was invented — there is none in the repo).
2. `printf 'G-XXXXXXXXXX' | npx vercel env add NEXT_PUBLIC_GA_ID production` — **`printf`, never
   `echo`**; a trailing newline gets inlined at build time and silently breaks the ID (this exact
   bug already hit `NEXT_PUBLIC_GA_ID` on meyng.com). `GA_ID` is `.trim()`ed as a second defence.
3. **Redeploy.** The client bundle inlines that variable at build time, so setting it alone will
   not switch the banner on.

## Also open

- **Legal wording is my judgment, not a lawyer's.** §6 says the `NEXT_LOCALE` cookie "est exempté
  de consentement". CNIL does treat a language-preference cookie as strictly necessary, and it is
  session-scoped (measured: no `Max-Age`, no `Expires`) and non-identifying — but if that clause
  makes anyone nervous, drop it and describe the cookie factually.
- `donation_complete` **fires on page view of `/donner/merci`, not on a verified payment.** Stripe's
  `success_url` carries no session id, so anyone landing on that URL registers a conversion, and no
  donation **value** is reported. Fixing it properly = add `?session_id={CHECKOUT_SESSION_ID}` plus
  a lookup route. Deliberately not half-built.
- Footer links to `/fr/privacy`, which 307s to the canonical `/fr/confidentialite`. Cosmetic.
- Everything still open from [2026-07-24](2026-07-24.md): the **Brevo key placement** (status not
  re-verified this session), fiscal-status/tax-receipt copy, favicon.ico, audit P1s.

## Key decisions

- **Supersedes the 2026-07-24 decision "Analytics = cookieless (Vercel) to stay banner-free."**
  Ad Grants conversion tracking requires the Google tag, which requires consent in France. Vercel
  Analytics stays; GA4 is added _alongside_ it, behind a banner, off by default.
- Consent denied by default rather than a soft/implicit opt-in — CNIL posture, and it keeps the
  site honest while the tag is off.
- Privacy §6 made **conditional** rather than rewritten once, so the page cannot become false in
  either direction as the tag is switched on or off.
- No measurement ID, no donation value, no KPI was invented anywhere in this session.
